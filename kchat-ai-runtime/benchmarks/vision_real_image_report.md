# VISION guardrail — real-image benchmark

Generated by `tools/benchmark_vision_real_images.py` from `datasets/vision/manifest.json` (real photographs) and the baked MobileCLIP-S2 prototype bank.

## Methodology & decision rule

Each image is decoded, preprocessed with the **on-device parity oracle** (`tools.gen_mobileclip_fixtures.python_reference_preprocess`: resize shorter side to 256 with antialiased **bilinear**, center-crop 256x256, scale to `[0, 1]` with **no mean/std normalisation** — MobileCLIP-S2's official transform), embedded by the MobileCLIP-S2 image ONNX, then L2-normalised.

Verdicts replay the **exact on-device trained-head chain** (`classify_from_embedding` with `head=Some(..)`): logits = `weight @ embedding + bias` -> **plain** softmax (the head learned its own scale) -> top-2 probability margin gate (min_margin=0.1) -> SAFE demotion (winner is SAFE or margin below threshold) -> confidence clamp [0.05, 0.95]. The trained head is a prototype-anchored linear probe: rows for categories with real pixels are calibrated on MobileCLIP-S2 embeddings; the remaining rows are frozen at the scaled prototype direction, so unsourced-category behaviour is identical to the v1 zero-shot path.
This makes the reported metrics faithful to runtime behaviour: low-margin harmful guesses are demoted to SAFE rather than counted as confident detections.

## Key findings

1. **Preprocessing bug fixed (headline).** Real-image testing exposed a production-critical bug: the pipeline preprocessed images as OpenAI-CLIP (224x224, bicubic, ImageNet mean/std) instead of MobileCLIP-S2's native transform (256x256, bilinear, no mean/std). That mismatch fed the tower a distribution it never saw, collapsing image/text cosine to ~0.03 (near-orthogonal) and macro-F1 to ~0.04. After correcting the constants + filter across the Python oracle, the ONNX export, and the Rust on-device path (`labels.rs`, `image_preprocess.rs`), embeddings recover to cos~0.9+ and macro-F1 rises to 0.9945.

2. **Trained head collapses the benign-child false-positive rate.** The zero-shot prototype path mis-routed benign photos of children into the SEXUAL_ADULT / VIOLENCE_THREAT / DEEPFAKE prototype directions (a well-known zero-shot CLIP modality-gap artefact) at a ~78% harmful-FP rate. The prototype-anchored linear head, calibrated on real MobileCLIP-S2 embeddings of the sourced categories, drives the measured CHILD_SAFETY harmful-FP rate down to 0% on this corpus (held-out generalisation is reported in `build-tools/compiler/data/vision_head.json`).

3. **Per-category CHILD_SAFETY cosine-margin floor (defence in depth).** Because the CHILD_SAFETY row stays frozen at a benign-clustering centroid (no sourceable CSAM), a runtime floor demotes any CHILD_SAFETY winner whose prototype cosine margin is below 0.05 to SAFE before the severity-5 floor fires — detection of a strong, corroborated signal still escalates, but a weak pixel-only guess on an innocent family photo no longer triggers critical_intervention. On this corpus it rescued 0 benign child images. The floor mirrors the Rust runtime default and the `vision_baseline.yaml` policy, so the benchmark verdict matches on-device behaviour.

4. **Honest limitation.** The head trains only two rows on real pixels (SAFE and DRUGS_WEAPONS); the other 15 rows — including CHILD_SAFETY — are frozen at the zero-shot prototype direction. The benign-child images in the corpus are labelled SAFE and train the SAFE row, so the CHILD_SAFETY row has no positive pixels and stays frozen by design; its benign-child false positives are handled instead by the runtime cosine-margin floor. Freezing guarantees *no regression* on unsourced categories but cannot *improve* their precision until real pixels are sourced. The margin gate still demotes low-confidence guesses to SAFE — the safer failure mode for an on-device guardrail.
